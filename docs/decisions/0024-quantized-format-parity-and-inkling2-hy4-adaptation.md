# ADR-0024: Zero-loss quantized-format compatibility (`FP8` / `MXFP8` / `NVFP4` / `GGUF` / `MLX` / sub-4-bit) and `Inkling 2` + `Hy4` family adaptation (`M8.1`–`M8.2`)

- Status: Accepted
- Date: 2026-11-23 (updated 2026-11-24)
- Source: user roadmap, `M8.1`/`M8.2` staging, and declarative JSON `ChatTemplate` confirmation following Hugging Face checkpoint & GGUF header verification

## Context

Live metadata and safetensors/GGUF header probes across Hugging Face frontier ecosystems established two converging requirements beyond Milestone `M7.8` (`ADR-0023`):

1. **New open-weight frontier families (`Inkling 2` and `Hy4`) introduce architectural primitives and native checkpoint formats not yet covered by `.amf` v0 (`src/format/amf.zig`) or `src/model/`:**
   - **Thinking Machines `Inkling 2` (`thinkingmachines/Inkling-2-Mini`, `Inkling-2-Small`)**: mixes `NVFP4` (E2M1 + E4M3 group-16 + per-expert F32 `amax` & `outer_scale_denominator`) and `MXFP8` (E4M3 + UE8M0 group-32) natively inside the base checkpoint, pairs `384`/`128` experts (top-8) with `k = 4` short convolutions (`attn_sconv`, `mlp_sconv`, plus dynamic `weight_proj` on global layers), low-rank relative positional bias (`d_rel = 16`, `rel_extent = 1024`), `q_l2_clip` / `rel_l2_clip`, `attn_sink_proj`, `gate_attn`, `attn_res` cross-layer queries, MLP & logit softcaps (`4` / `25` / `30`), router bias with `route_scale = 8.0`, an `o200k`-like BPE tokenizer (`vocab = 199,998`, `merges = 424,413`, `ignore_merges = true`), role/content chat markers (`<|message_user|>`, `<|content_thinking|>`, etc.) instead of ChatML, a 23-layer ViT, and `DFlare` (`3L`/`5L` `block_size = 8`) drafting. `Inkling-2-Mini` uses `LoopSchedule`-style 3-pass recurrent depth over `layers 6..17` with `controllers.{attn,k,v,mlp}.{down,forget,gain}_weight` and `18.78 GiB` total checkpoint size (`~17.6 GiB` backbone without vision, sitting right at the `24 GB` M4 `18,186 MiB` ≈ `17.76 GiB` wired budget before KV/scratch).
   - **Tencent `Hy4` (`Hy4-preview`, `Hy4`, `Hy4-flash`)**: pairs `DeepSeek`-like BPE pre-tokenization + `<｜* :opensource｜>` chat templates with iHC `hc_mult = 4` residual streams, MLA (`q_lora` `2048`/`1024`, `kv_lora` `512`), `learnable_sink_param`, `linear_gate` (elementwise), `swiglu_limit = 10.0`, `Gated DSA` (`IndexCache` period-4 `full`/`shared` or `Hy4-flash` `IndexPool` compressed indexer + `1:3` `SWA` `512`), `512`-expert `LatentMoE` (sigmoid router + bias, `routed_scaling_factor = 3.998`), `sandwich_norm`/`post_proj_norm`, `10.3M`-per-head `63.5B` Engram tables (`F8_E4M3` quantized variants), `40L`/`27L` AnyRes `ViT`, and `5L` `DFly2` (`confidence_head`, `hidden_correction`, `mtp_fusion`).
2. **Existing offline tools and Metal/SME2 kernels reject nearly every published quantized distribution of these models:**
   - `tools/src/aminfer_tools/amf.py` (`L919–1008`) hard-requires `MLX` `U32` `.weight`/`.scales`/`.biases`, `bits in {2, 3, 4}`, `group_size = 64`, and `DType` in `{f16, f32, q4_affine, q3_affine, bf16, u32, q2_affine}` (`src/format/amf.zig` `L113–135`).
   - Published checkpoints instead span **six incompatible quantization conventions**: ModelOpt `MXFP8` (`UE8M0` `[1, 32]`, used even by `tencent/Hy4-preview-FP8` despite its `-FP8` repo name), `[128, 128]` block FP8 with either `F32` (`Hy4-FP8` / `Hy4-flash-NVFP4`) or **`BF16`** (`Hy4-flash-FP8`) inverse scales, per-row `F8_E4M3` + `F32` Engram tables (`Hy4-flash-NVFP4`), stacked and unstacked `NVFP4` (`weight_scale` E4M3 + `weight_scale_2`/`weight_global_scale`/`amax` F32), extended MLX affine bit-widths/group sizes (`5/6/8-bit`, `g32`/`g128`, plus `nvfp4` mode overrides), and dynamic-quant `GGUF` files combining upstream `Q*`/`IQ*`/`TQ*`/`MXFP4` with **`NVFP4` (`id 40`)**, **`Q2_0` (`id 42`)**, and **`F8_E4M3` (`id 43`)** (forced by non-256-divisible hidden dims such as `Inkling-2-Mini` `intermediate_size = 1152`) alongside colliding custom fork type IDs (`AngelSlim/Hy4-preview-STQ1_0` overloading `id 43` at `1.312 bpw`).

Loading unaligned GGUF or FP8 safetensors directly at runtime would violate [ADR-0002](0002-page-alignment-and-zero-copy.md) (`16 KiB` alignment) and [ADR-0006](0006-amf-cold-experts-direct-io.md) (`F_NOCACHE` wired direct I/O). Conversely, force-requantizing published `FP8`, `MXFP8`, `NVFP4`, or `IQ`/`K` weights into `q4_affine` would inject avoidable double-quantization error.

The user therefore confirmed scheduling **Milestone `M8`** after `M7.8` in two sequential sub-milestones: **`M8.1`** (`W21`, `W22`, `W24`, `G23`, `G24`, `C25`: zero-loss multi-format `.amf` + register-dequant Metal/SME2 kernels, offline `GGUF` streaming repacker, multi-dialect tokenizers + declarative JSON `ChatTemplate` state machine, and `KL`/top-1 quality gate) followed by **`M8.2`** (`W23`, `G25`, `D14`, `C26`: `Inkling 2` and `Hy4` operator suites, `DFlare`/`DFly2` block-parallel draft heads, NVMe cold-expert/Engram placement, and end-to-end local `Inkling-2-Mini` + `hy4-preview-tiny-random` verification on the `24 GB` M4 baseline).

## Decision

### 1. Native lossless `.amf` dtypes and bit-exact register dequantization (`W21`, `G23`, `C25`, M8.1)

- **Zero double-quantization invariant and bounded-disk stream packing:** Every supported checkpoint format gets a native `.amf` representation and native Metal 4 / SME2 dequantization path whose mathematical output matches the source format's reference decoder (up to FP32 summation order). Offline `tools/` performs **lossless relayout only**: `16 KiB` blob alignment (`APPLE_PAGE_SIZE`), per-expert slicing of stacked expert tensors (every row already an integer multiple of block size), contiguous scale placement alongside packed codes (`params_offset` `64 B`-aligned), Q/K row-permutation reversal where required (`GGUF` rotary permutations), and optional HTTP Range / direct-to-`.amf` stream packing so constrained single-disk hosts do not duplicate full source + `.amf` payloads simultaneously. No requantization is applied when importing an already-quantized checkpoint.
- **New `.amf` `DType` / `QuantScheme` extensions (`src/format/amf.zig`, `tools/src/aminfer_tools/amf.py`):**
  - `fp8_e4m3_block` (`128×128` E4M3 weights with `f32` or `bf16`-promoted-to-`f32` block scales), `fp8_e4m3_row` (per-row `f32` scale, e.g. `Hy4-flash` Engram tables), and `fp8_e4m3_tensor` (per-tensor / per-channel scale).
  - `mxfp8_g32`: E4M3 weights paired with `1 B` `UE8M0` power-of-two exponent scales per `32` elements (`~8.25 bpw`).
  - `nvfp4_g16`: E2M1 nibbles packed `2` weights/byte (`0.5 B/el`) paired with `E4M3` micro-scales per `16` elements (`~4.5 bpw`) and a per-tensor or per-expert `f32` global outer scale (handling both `weight_scale_2` / `weight_global_scale` multiplicative conventions and `amax / outer_scale_denominator`).
  - `mlx_affine` parity extensions: add `q5_affine`, `q6_affine`, and `q8_affine` (`u32` packed weights + `half2(scale, bias)`), parameterize `group_size` across `{32, 64, 128}` (`ADR-0014` `comptime` + Metal function constants), and map MLX `mode: "nvfp4"` directly onto `nvfp4_g16`. Note that per-tensor/per-expert mixed-precision checkpoints (`oQ4e`, `UD-*`, `MIXED_PRECISION`) map naturally onto `G13` per-tensor `QuantScheme` buckets (`ADR-0017`) while preserving the prohibition on intra-tensor bit mixing.
- **Metal 4 and ARMv9.2 SME2 dequantization (`G23`, `C25`):**
  - Single-token decode (`M = 1`) is DRAM-bandwidth-bound on Apple Silicon; kernels convert `E4M3` / `E2M1` / `UE8M0` / `K`-quant codes to `float` / `half` strictly in registers, accumulate in `FP32`, and pass an `M = 1` memory-bus utilization gate against baseline `q4_affine` (`98.8 GB/s`, `82.3%` on M4).
  - Wide prefill and batched verification (`M >= 16`) dequantize weight tiles to `fp16` (or direct `E2M1` `NAX` tensor-ops via `G17` `ami_fp4_e2m1_gemm_nax` on `Apple10+`) and feed `G15` / `G17` / `G19` MMA paths.
  - Extend `src/cpu/sme2_kernels.s` (`C25`) with `luti4` / `ZT0` microkernels for `NVFP4`/`MXFP4` (`E2M1` + `E4M3`/`UE8M0` scales) and threadgroup/panel lookup helpers for `Q2_0`/`TQ`/`IQ2` cold/draft projections under existing `C13` bus-contention and `0` `[sp` spill invariants.

### 2. Offline lossless `GGUF` -> `.amf` repacker and fork safety (`W22`, M8.1)

- **Strictly offline conversion in `tools/` (`0` runtime GGUF parsing, `0` `llama.cpp` C dependency):** Implement a pure-Python-stdlib GGUF v2/v3 streaming converter in `tools/src/aminfer_tools/gguf.py` integrated into `aminfer-tools pack-amf`. Runtime continues loading only `.amf` files via `F_NOCACHE` (`ADR-0006`).
- **Supported standard upstream `ggml_type` set:** `F32` (`0`), `F16` (`1`), `Q4_0` (`2`), `Q4_1` (`3`), `Q5_0` (`6`), `Q5_1` (`7`), `Q8_0` (`8`), `Q2_K` (`10`), `Q3_K` (`11`), `Q4_K` (`12`), `Q5_K` (`13`), `Q6_K` (`14`), `IQ2_XXS` (`16`), `IQ2_XS` (`17`), `IQ3_XXS` (`18`), `IQ1_S` (`19`), `IQ4_NL` (`20`), `IQ3_S` (`21`), `IQ2_S` (`22`), `IQ4_XS` (`23`), `IQ1_M` (`29`), `BF16` (`30`), `TQ1_0` (`34`), `TQ2_0` (`35`), `MXFP4` (`39`), **`NVFP4` (`40`)**, **`Q2_0` (`42`)**, and **`F8_E4M3` (`43`)** (verified in upstream `llama.cpp` `ggml/include/ggml.h`). `1–16 KiB` `IQ` codebooks stay resident in Metal threadgroup SRAM for `G23` register decoding.
- **Per-tensor dispatch, shape/byte integrity gate, and explicit fork rejection:**
  - Read `ggml_type` per tensor rather than assuming filename labels (dynamic GGUFs such as `Mini` `UD-*` switch to `Q2_0` / `NVFP4` / `MXFP4` on `1152`-wide `ffn_down_exps` because `1152 % 256 != 0`, and `Inkling-2-Mini` GGUFs unroll loop layers into `block_count = 48` metadata while packing `24` physical layer weight sets).
  - Verify `actual_tensor_bytes` (from sorted GGUF tensor offsets / file size) against `ggml` expected row-padded byte size for every tensor. **Fail hard on any mismatch or unknown / colliding fork type** (specifically catching ID collisions such as `AngelSlim/Hy4-preview-STQ1_0` using `type 43` at `1.312 bpw` vs upstream `GGML_TYPE_F8_E4M3 = 43` at `8.0 bpw`), as well as unsupported formats (`STQ1_0`, `SPARK` custom forks if non-standard, `VQ-GGUF`, `EXL3`). `AngelSlim/Hy4-flash-GGUF` `IQ2_AH` is accepted because inspection confirmed it uses standard `IQ2_XXS`/`Q4_K`/`Q8_0`/`BF16`/`F8_E4M3` types.
  - Normalize `blk.N.*` tensor names to canonical internal names, deduplicate unrolled recurrent references, route companion `mmproj-*.gguf` vision projectors (`clip` `23L`/`27L`) into `W20`/`G22`, emit standalone `arch=dflash` GGUFs as `D14` draft bundles, and prefer canonical Hugging Face `tokenizer.json` / `chat_template.jinja` while cross-checking vocab size and special tokens against GGUF metadata.

### 3. Activation-quantization emulation and sub-4-bit quality preservation (`W21`, `G24`, `W24`, M8.1)

- **Weight-only default + opt-in activation emulation (`G24`):** Default execution dequantizes weights directly to `FP16`/`FP32` without quantizing intermediate activations (`input_activations` skipped for speed). Provide `--act-quant emulate` (`mxfp8_g32`, dynamic `group_size=128` FP8, and per-token `group_size=16` NVFP4 including `fouroversix_mae` block selection) for strict reference parity testing; per-model defaults remain gated by capability-gate evaluation.
- **Sub-4-bit (`< 4 bpw`) handling:**
  - When consuming **published** low-bit checkpoints (`IQ1_S`/`IQ1_M`, `IQ2_*`, `Q2_0`, `TQ1_0`/`TQ2_0`, MLX `2-bit`), aminfer preserves the published weights with zero additional conversion loss (`W21`/`W22`) and surfaces the checkpoint's baseline degradation transparently.
  - When producing **native low-bit builds** from BF16/FP8/MXFP8/NVFP4 sources, reuse offline `GSQ + RCO` (`ADR-0017`, `W14`/`W17`, optionally importing GGUF `imatrix` statistics as an extra sensitivity prior): keep attention projections, routers (`gate.weight` & `F32` bias/correction_bias), `shared_expert`s, `embed`/`lm_head`, recurrent controllers, `sconv`, norms, iHC parameters, `MTP`/`DFlare`/`DFly2` heads, and `ViT` encoders at high precision (`>= q4_affine` / `bf16` / `f32`), compressing only cold routed experts (`W8`) to `q3_affine`/`q2_affine`.
- **Mandatory capability quality gate (`W24`):** Before any new dtype kernel or quantization profile is promoted, measure logits KL divergence, top-1 token agreement, and short deterministic code/math evaluation accuracy against the source BF16 / reference checkpoint (in addition to `zig build test` numerical tolerances and `swapouts_delta = 0`).

### 4. Two-phase delivery (`M8.1` -> `M8.2`), declarative JSON `ChatTemplate`, and `Inkling 2` + `Hy4` adaptation (`W23`–`W24`, `G25`, `D14`, `C26`)

- **Sub-milestone `M8.1` — Multi-format quantization substrate, tokenizers, declarative `ChatTemplate`, and `KL` gate (`W21`, `W22`, `W24`, `G23`, `G24`, `C25`):**
  1. Multi-format `.amf` relayout + HTTP Range / bounded-disk stream packing (`W21`), pure-stdlib `GGUF` -> `.amf` streaming repacker with byte-length fork guard (`W22`), bit-exact Metal 4 (`G23`), `--act-quant emulate` (`G24`), ARMv9.2 SME2 (`C25`) register-dequant kernels, and the `W24` `KL` / top-1 / short code-math capability quality-gate harness.
  2. **Tokenizer generality and declarative `.amf` JSON `ChatTemplate` (`W24`)**: extend `src/model/tokenizer.zig` with `o200k`-style regex splitting + `ignore_merges = true` (`Inkling 2`) and full Hugging Face `added_tokens` special-token matching (`Hy4` `<｜hy_*｜>`). Rather than embedding a runtime Jinja2 AST interpreter, offline `tools/` compiles Hugging Face `chat_template.jinja` / `tokenizer_config.json` into a declarative `.amf` JSON `chat_template_spec` (`chatml`, `deepseek`, `inkling2`, `hy4`, plus custom role/thinking/tool/EOS delimiter overrides), rendered at runtime by a deterministic zero-allocation Zig state machine replacing hardcoded `<|im_start|>` builders across `src/cli/chat_repl.zig`, `src/server/http_sse.zig`, `src/sdk/c_api.zig`, `src/model/tokenizer.zig`, `src/main.zig`, and `src/bench/runner.zig`.
- **Sub-milestone `M8.2` — `Inkling 2` and `Hy4` operator suites, `D14` block-parallel draft heads, and local M4 end-to-end verification (`W23`, `G25`, `D14`, `C26`):**
  1. **`Inkling 2` runtime (`W23`, `G25`, `C26`)** and end-to-end **`Inkling-2-Mini`** on local `24 GB M4`: reuse `ADR-0019` `LoopSchedule` (`core_start = 6`, `core_end = 18`, `num_passes = 3`) plus `controllers.{attn,k,v,mlp}` & `middle_cycle_cross_pass_{kv_}queries`, extend `G8` `ami_gdn_conv1d_silu` (`src/kernels/hybrid_ops.metal` `L2216`) to `k = 4` static & global dynamic `sconv`, add Metal kernels for low-rank `rel_logits_proj` attention, `q/rel_l2_clip`, `log_scaling`, `attn_sink_proj`, `gate_attn`, `attn_res`, softcaps (`4`/`25`/`30`), and routed-expert `bias + route_scale`, reuse `HybridKvRing` for 1024-token SWA layers, and route cold routed experts over `C3`–`C5` NVMe direct I/O when running native `~17.6 GiB` backbone (`+ 0.59 GiB` MTP) inside M4's `18,186 MiB` wired budget (while `UD-IQ3_XXS` `10.9 GiB` or `UD-Q4_K_XL` `16.4 GiB` + selective cold-expert NVMe fit with KV headroom and zero swap).
  2. **`Hy4` family operators (`W23`, `G25`, `C26`)**: reuse `G7`/`G10`/`G11`/`C10`/`W20`/`G22` and add `IndexCache` period-4 `full`/`shared` reuse, `Hy4-flash` `IndexPool` compressed indexer (`compress_ratio = 4`, `group_topk = 512`, `candidate_topk = 2048`), `LatentMoE` (`routed_expert_up/down_proj`, `combine_output_norm`), sigmoid router + `e_score_correction_bias`, `linear_gate`, `learnable_sink_param`, `swiglu_limit = 10`, `sandwich_norm`, `post_proj_norm`, and `F8_E4M3` per-row Engram NVMe streaming (`C26` over `C10`).
  3. **Block-parallel speculative drafting (`D14`)**: add `DFlare` (`3L`/`5L` `block_size = 8` `rnn_hidden` Markov + `markov_w1` / `mask_embed` + standalone `arch=dflash` GGUF) and `DFly2` (`5L` `block_size = 7` reading `dfly_target_kv_layers`, `confidence_head`, `hidden_correction`, `mtp_fusion`) under `DraftSource` and `G5`/`D9` verification.
  4. Validate `hy_v4` / `hy_v4_vl` / `hy_v4_flash` and `inkling2` parity locally via `yujiepan/hy4-preview-tiny-random` (`21 MB`), `Inkling-2-Mini`, and synthetic fixtures on `24 GB M4`; treat full-scale `Inkling-2-Small` (`363.27 GiB` native; `118.8`–`190.9 GiB` GGUF; `78.7`–`82.3 GiB` 2-bit MLX fits `128 GB` Max), `Hy4-flash` (`267.4 GiB` FP8 / `150.0 GiB` NVFP4 fits `256–512 GB`; `76.3 GiB` MLX 3.5-bit fits `128 GB` Max), and `Hy4`/`Hy4-preview` (`219.2 GiB` `IQ1_M` fits `512 GB` Ultra; `403.6–456.7 GiB` 4-bit/`NVFP4` & `732–758 GiB` FP8 require `512 GB` / `TB5` cluster) as hardware-gated targets analogous to `M7`.

## Consequences

- **Positive:** Consumes `FP8`, `MXFP8`, `NVFP4`, `MLX` `2..8-bit`, and standard `GGUF` checkpoints natively without double-quantization fidelity loss or runtime unaligned reads; adapts `Inkling-2-Mini` locally to the `24 GB` M4 baseline; generalizes tokenization, chat formatting, and Metal/SME2 operator coverage cleanly across both `Inkling 2` and `Hy4` families; and enforces explicit byte-level verification + capability gates to reject incompatible fork encodings early.
- **Negative / trade-offs:** Expands `.amf` `DType` enum and Metal function-constant pipeline matrix (increasing `.metallib` size and test surface); adds an offline Python GGUF reader to maintain as upstream `llama.cpp` evolves `>= 40` type IDs; and keeps full-size `Small`/`Hy4`/`Hy4-flash` runs gated on higher-memory Macs or clusters while `Mini` + tiny/synthetic fixtures prove functional parity on M4.
